# 对话答案的来源核验

聊天仍通过 `POST /api/v1/knowledge/chat` 返回 SSE，调用方不需要修改请求。

每轮会先以当前用户权限和知识库范围重新检索；后续仍可使用 `knowledge_search` 追加检索。
历史消息只帮助理解指代，上一轮的来源编号不构成本轮证据。编号在本轮追加检索时保持稳定。
初始检索从完整用户历史保留最近的显式项目标识，当前问题出现新标识时覆盖旧主体；不会从历史助手答案提取事实。
包含多个分项的问题至多执行三次初始检索，合并去重后提供证据。每次仍使用同一用户和知识库权限过滤。
整轮证据最多 16 个来源、24,000 字符，已有编号不会因追加检索改变。
模型最多追加三次工具检索、四次模型交互。耗尽预算时停止工具循环，基于已经可见的来源生成一次结构化草稿，仍须经过全部来源核验；其他上游故障不会触发该路径。

最终草稿使用 `claims / evidence / insufficient` JSON：每条事实包含来源编号及该来源可见
`content` 中的 `passage_ids`。片段编号由服务端分配，模型只选择编号，原文引句由服务端提取，
避免抄写时空格、换行、标点差异造成误拒。服务端检查结构、来源和片段编号，然后另行调用已配置的聊天模型，
核验选中证据是否支持整条陈述、是否完整覆盖问题要点，以及 Wiki 与原始文件的归属是否被混淆。核验只收到实际提供给
生成模型的片段，不使用 `wiki.page.content` 等额外全文。
单条事实核验与整题完整性检查使用独立请求：前者一次只收到一个事实及它选择的原文片段，
不会收到其他条目或未引用来源的内容；后者读取本轮全部可见来源，发现遗漏的可回答事项。
前者只接收实体、来源、日期和用户假设等解释约束，不接收整道问题的任务清单，避免把回答其他要点的责任加到单条事实上。
相关性也在整题检查中逐条判断，避免将必要的计算前提误判为未回答整个问题。
初次判定为非原子的条目，再以当前 `text` 单独复核；复核不接收问题、其他条目或来源段落，
避免将引句里的其他属性误算进当前陈述。真实并列的独立事实仍须拆分，不能通过复核绕过。
单条核验最多并发三个请求；完整性检查可同时进行。该隔离避免将全答案的属性误判为每条事实的属性，
也避免核验器借未引用资料补齐某条陈述的证据。

结构或语义未通过时，服务端将具体问题交给模型修正，最多两次；每次均执行相同核验。仍失败则发送
`error`，不输出未经核验的草稿，也不把核验失败伪装为“没有资料”。通过后，服务端为每条
事实渲染 `[n]`。资料不足的说明使用固定文案，不需要虚构引用。

核验器使用按本次答案生成的 JSON Schema 约束条目数量、编号和逐来源判定。上游明确不支持
`json_schema` 时才回退 `json_object`。无论采用哪种模式，都在本地检查遗漏、重复或越界。
核验器自身返回不合格 JSON，或虽能解析但缺少条目/来源时，以相同证据和规则请求一次格式修复；
仍不合格则报核验服务错误。格式修复与答案修正分别计数；核验 HTTP 故障也不会触发答案重写。
核验 JSON 因输出长度被截断时，同样只允许一次格式修复，不能直接接受截断输出或借此修改答案。

多项问题缺少可由现有资料回答的要点时，同样触发修正。用户限定询问 Wiki 记载时，应报告
Wiki 内容；询问最新事实或比较版本时再区分版本。明确的 Wiki/原文限定会过滤生成、工具检索与核验的来源，
对比两者时保留双方。明确写出的算式通过有界表达式解析器，以精确有理数检查四则运算、括号、连乘和小数，
避免截取算式后半段产生误判；支持常见费用单位（如 `1500元/副本/月 × 7副本 = 10500元`）。
生成模型可提交 `calculation: {"expression":"40*3*2-5","unit":"元"}`；其中表达式只允许数字、算符和括号。
后端精确计算结果并将 `40*3*2-5=235元` 附在该事实文本中，再核验原始数值的来源。模型修正使用
JSON Schema 约束字段和表达式格式。兼容原有直接写在 `text` 中的完整算式。
生成和纠错要求每一步都直接展开原始数字，不用中间结果常数或条目索引；每条选择全部原始数值的证据，避免索引混淆和中间证据丢失。
后端兼容解析 `expression` 中的 `$0` 等本回答前序计算引用（从 0 开始），将其展开为原始数字的表达式，
自动继承该步骤的全部原始来源和片段，并处理元/万元/亿元换算；前向、循环引用或无效原始证据会拒绝。
展示时按运算优先级去除冗余括号，使完整原始算式更易读；不折叠或隐藏原始数字。
同一来源的多个片段选择合并为一次引用，越界或无效片段仍会拒绝。
非计算推论可用 `depends_on` 引用当前回答前序条目，继承完整原始证据；不会把上一轮助手文本当证据，
也不允许前向或循环依赖。修正时要求每条为独立陈述并重新核验；含逗号的名称可加引号原样保留。
复合事实会局部拆分，并分别选择原有片段；其他已正确条目保持内容，后续依赖索引随拆分重排。
同一草稿中已明确识别的复合句在一次修正中一起处理，至多八句、并发三个请求，避免每拆一句就消耗一次答案修正机会。
拆分后的所有条目仍重新执行相同的结构、支持性、相关性和完整性核验，不能借拆分输出未核验内容。
修正答案使用可变长事实数组，并省略非计算依赖字段；推论直接选择全部原始证据，避免索引误写。原有有效依赖仍兼容解析。
货币金额不在所引片段中直接出现时，必须给出以该金额为结果的完整算式，避免仅给合计而遗漏计算分项；
元、万元、亿元之间的等值写法不强制重复计算，显式不同货币单位会先换算。除零、超长表达式、过深括号和
数值溢出会拒绝。解析器只校验数值与货币换算，分项的来源、时间和物理量纲仍需经过语义核验。
分步计算可使用本回答前序已校验算式的货币结果；后续步骤必须保留其全部原始来源和片段编号，
并展示当前步骤的算式。不能引用未来条目或历史助手回答来建立计算依赖，整个答案仍须通过语义核验。
核验还会检查条目是否包含多个独立事实；这些事实必须拆分后分别绑定来源，避免句尾共用引用造成来源归属错误。
每条事实还必须直接回答问题；检索到其他项目时，不补充其背景来解释拒答。完全没有所问事实时，
返回空 `claims` 并使用固定拒答文案；部分问题有依据时保留该部分的事实和引用。
核验结果必须逐条覆盖每个引用来源，分别说明它对该事实的实质支持；整体结论正确也不能放过无关引用。
来源判定缺失、编号重复或不属于该条事实时，同样不通过核验。
原始观测值与规则阈值分别绑定各自来源；比较结论或跨文档实体映射可联合引用必要的前提。
记录只提供实测数据而未直接写结论时，仍允许按有效规则推导达标与否；未核准草案不能替代正式生效规则。
对选中片段的结构化文本字段（`标签：标识符`），本地还会检查标识符内部空格是否被改写；普通数值和单位不受此检查影响。

`status` 新增 `verifying` 和 `correcting`；`sources` 仍即时发送。`delta` 在核验完成后才发送，
因此首段正文会晚于原来的直接流式输出。客户端断开仍会取消检索及上游请求。

核验使用 `LLM_API_URL / LLM_MODEL / LLM_API_KEY`，每次核验或修正的 HTTP 请求最长 90 秒，
请求复用同一 HTTP 连接池；仅建立连接失败时延迟 250 毫秒重试一次，HTTP 错误、正文读取失败和语义拒绝不会触发该重试。
整个对话仍受 300 秒限制。模型判定仍存在误差，需要结合独立端到端评测持续验证；不能把
“通过模型核验”等同于事实正确的保证。

验证命令：

```sh
cd frontend && npm install && npm run build
cd ..
cargo test --lib api::chat
cargo test --test chat
cargo build --locked
```

`tests/chat.rs` 覆盖真实工具检索的权限范围、多轮历史、错误草稿的修正、真实引句与错误结论
的拦截、上游故障的脱敏，以及答案缓冲期间的断连取消。端到端评测应对本地实例重新发问，
不能只重新评审旧答案。
回归测试还覆盖正确结论附带无关引用、拒答解释混入其他项目事实，以及部分可回答时保留已知答案。
新增回归覆盖完整连乘和带单位算式、错误运算、跨轮项目标识、Wiki 范围隔离、核验条目/引用遗漏的格式修复、
持续格式故障、核验 HTTP 故障，以及上游明确不支持 JSON Schema 时的兼容回退。
